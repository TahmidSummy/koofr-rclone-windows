3. What the research said

  • HTTP/2 + Koofr is a known problem. Forum users report Koofr dropping to single-connection speeds unless --disable-http2 is used, which is blamed on a Go library bug. The claim was that it only hurts parallel transfers. My tests found it also hurts one big upload, by 3Ã—.
  • Koofr has no multipart/chunked upload in rclone, so one big file uploads as one stream. Your ~10 MiB/s single-file upload is close to that limit. Many files in parallel go faster.
  • Mount reads used to be single-stream. A 2023 thread found mount downloads 20Ã— slower than rclone copy, and nothing fixed it then. rclone 1.68 (2024) added --vfs-read-chunk-streams for exactly this. Nobody in the Koofr threads had tried it, and it's the biggest win here.
  • HTTP/2 can't be turned off in the config file the normal way. The docs do list override.disable_http2 as a per-remote override, but I didn't test it, so the flag on the command line is the reliable option.

5. Koofr quirks found

  • Rate limit (429) at about 50+ requests/s sustained. rclone doesn't retry these, so files fail. Fix: --tpslimit 40.
  • Occasional dead connections that sit silent until the timeout. Seen once in 70 runs (5-minute freeze). Fix: --timeout 1m.
  • About 0.3 s per file to open or download any file, however small. Parallelism is the only cure.
  • Speed varies a lot through the day. The same test ran anywhere from 1Ã— to 2Ã— its slowest speed across the evening.
  • No change notifications. Changes made elsewhere only appear when --dir-cache-time runs out.
  • HTTP/2 is bad for Koofr, especially single-stream and low-parallel transfers.

6. What wasn't tested

  • --buffer-size, --vfs-read-ahead sizes, --attr-timeout, and --use-mmap were left at your current values.
  • Explorer thumbnails, video seeking, and apps with lots of random reads. The tests used straight sequential reads.
  • Whether --timeout 1m cuts off a legitimately slow transfer. It shouldn't, because the timeout only counts time with no data moving at all. Update: it did. A folder rename is a request with no data moving until Koofr finishes, so 1m cut it off (RESEARCH.md §13).
  • Multi-hour stability with the new flags. Watch the log for a few days after switching.
